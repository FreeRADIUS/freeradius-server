= Submitting a Patch by Email

The preferred route for proposing changes is a
xref:gitpr.adoc[GitHub pull request], which provides a stable diff,
review discussion, and a record of verification.

For contributors who cannot use GitHub, a small plain-text patch can
be discussed on the developer mailing list. Email delivery does not
guarantee review or acceptance, and contributors may be asked to
submit a pull request for larger changes.

== Create a Unified Diff

A unified diff shows which lines changed, with surrounding context.
Use `diff -u` for one file or `diff -urN` for a directory comparison.
Create the patch relative to the source-tree root so reviewers can
identify the affected paths.

For a single file:

[source,shell]
----
SRCTREE=/home/user/src/freeradius-server
MYFILE=src/modules/rlm_foo/foo.c

cd "$SRCTREE"
cp "$MYFILE" "$MYFILE.orig"
# Edit the working file.
diff -u "$MYFILE.orig" "$MYFILE" > /tmp/change.patch
----

When working with Git, `git diff` or `git format-patch` can also
produce reviewable patches. Review the resulting file before sending it.

== Describe the Change

Include:

* The affected FreeRADIUS version or branch.
* The problem being corrected and the intended behavior.
* Relevant reproduction steps, tests, and observed results.
* Any checks not performed and any known limitations.

Ensure the patch does not contain credentials, personal information,
or unrelated changes.

== Send the Patch

Use the
mailto:freeradius-devel@lists.freeradius.org[FreeRADIUS development mailing list]
for technical patch discussion. Check the current
https://freeradius.org/support/[project support page] for mailing-list
instructions and alternatives.

Small patches sent inline as plain text are easy to quote and comment
on in email replies. For changes that would be difficult to review
inline, propose a GitHub pull request or ask how reviewers would
prefer to receive the patch.

Do not rely on arbitrary file-size thresholds as a measure of
whether a change is worth reviewing. Scope, clarity, reproducibility,
and the available review process are more useful criteria.
